# MASTER@DE'GENIUS — UI/UX Remediation Specification

Scope: student PWA, 360–430px phone primary, desktop sidebar secondary. No code changes in this pass.

## 1. Additional audit (areas not covered deeply before)

**Auth** — Visually the most internally consistent cluster already (same card, heading, spacing). Gaps: no show/hide password toggle; no live "passwords match" feedback before submit; target-score/number bounds enforced only via HTML attributes, no inline validation copy; login success state is carried via a `?password=updated` query flag (fine, but survives back-button re-visits).

**Onboarding** — Honest about scope (only JAMB live, others marked "coming later" — keep). Gaps: all 3 steps live in `useState`, so a reload mid-flow silently discards progress with no warning; step 3's numeric bounds (180–400) aren't validated until server round-trip.

**First-time/empty states** — Home's "everything empty" case (new user, no attempts yet) collapses to header + one CTA panel + quick actions + two zeroed stat cards — thin and CTA-light for a first run. `/progress`, `/progress/mistakes`, and `PracticeSetup`'s "no subjects" case all have real, differentiated empty copy already — good pattern, just not applied to Home's cold-start.

**Loading/error/offline** — Only `/progress` has `loading.tsx`/`error.tsx`. Every other data-driven route (`/home`, `/practice`, `/mock`, `/me`, `/exam/[id]`, `/practice/session/[id]`, `/progress/mistakes`, `/progress/results/[kind]/[id]`) has neither — slow fetches blank-flash, thrown errors fall to Next's unbranded default error page. In-page async actions ("Building session…", "Building your paper…") already use a good spinner+label micro-pattern — keep it, just don't conflate it with route-level skeletons.

**PWA** — `sw.js` is genuinely solid: network-first navigations, static+icon caching, opt-in image caching via `SAVE_MEDIA`, no forced `skipWaiting` (won't kill an in-progress exam). Gaps: install/update banner appears on `/home` immediately post-onboarding, before any value is demonstrated; once dismissed there's no way to resurface it (no settings entry in Profile).

**Mobile keyboard/safe-area** — No text-entry answer types exist yet, so keyboard-covers-content risk is currently moot. Bottom sheets correctly use `dvh` with internal scroll. Real bug: exam/practice runners clear the tab bar at `bottom-[calc(4.25rem+...)]`, but Practice Setup's sticky CTA bar uses `4.5rem` — inconsistent, not a design choice.

**Full CBT lifecycle** — The offline/session engine (`use-session.ts`, `queue.ts`, `storage.ts`, `clock.ts`, Web-Locks single-editor guard, monotonic clock, conflict/revision handling, legacy-localStorage migration, auto-submit-on-expiry with retry) is production-grade. **Do not touch this logic** — remediation here is UI-only. Real UI gaps: mock exam has an explicit "I'm ready to begin" consent gate, timed practice does not, despite both being irreversible once started; timed practice's duration is invisible until the runner is already running; "Exit" during practice just navigates away, relying on the browser's generic `beforeunload` prompt rather than an in-app confirmation; conflict resolution ("Keep this device's changes") is a plain box mid-page for a high-stakes decision.

## 2. Design system (consolidate, don't invent)

Keep the existing brand system — it's already coherent, just not consistently applied. No new colors.

- **Color**: `brand` scale (50/500/600/950, already in `tailwind.config.ts`) is the only blue. Retire raw Tailwind `blue-*`/`indigo-*` utility usage across home/progress/results/mistakes/offline-launcher. Retire `app/globals.css` custom properties (`--brand`, `--success`, `--danger`, `--warning`) — formalize `success` (emerald), `danger` (red), `warning` (amber) as named scales in `tailwind.config.ts` instead, using the exact hexes already in use so no visual change occurs, just one source of truth. Neutrals stay Tailwind `slate`.
- **Typography**: keep Public Sans + IBM Plex Mono (`.mono-number`) pairing. Fix the drift into one scale: Display 40–48px/black/-0.04em (score hero only) · H1 24–28px/**extrabold**/-0.02em (page titles — currently sometimes `black`, too heavy for a frequent element) · H2 15–16px/bold (section titles) · Eyebrow 10–11px/**bold**/uppercase/0.14em (currently mixes bold/extrabold) · Body 14–15px/regular-medium · Caption 11–12px/medium, slate-400/500 only (never slate-300 for real copy — reserve 300 for placeholders).
- **Spacing**: keep Tailwind's 4px scale. Card padding rule: `p-4` mobile / `p-5`–`p-6` sm+ for standard cards, `p-6`/`p-8` for hero/auth cards only — stop the p-5/p-6/p-7 mixing on structurally identical cards.
- **Radius** (3-tier rule, fixes the xl/2xl/3xl chaos): `rounded-xl` (12px) controls — buttons, inputs, chips, tiles. `rounded-2xl` (16px) standard cards/panels — the default. `rounded-3xl` (24px) hero containers only — auth card, onboarding card, result score banner, bottom-sheet top corners. `SectionPlaceholder`'s outer card moves 3xl→2xl (it's a standard card, not a hero).
- **Card types** (name them so they're reused, not reinvented): `StatCard` (number+label), `ActionTile` (icon+label+helper, links out), `ListItemRow` (title + trailing value/action), `HeroPanel` (dark slate-950 full-bleed, `cta`/`summary` variant — collapses Home's CTA panel and Result's score banner into one component), `FormCard` (bordered control group), `ChecklistCard` (icon-prefixed confirmations, used by Mock Setup today).
- **Buttons**: extend the existing `Button` (don't replace) — keep `primary/secondary/ghost/danger`, add `dark` (slate-950/white — currently hand-rolled on every "commit" action: sign-in, finish-session, resume-exam). Keep `sm/md/lg`, add `xl` (52–56px) for the CBT-critical actions that currently hardcode `h-14`/`52px` by hand. Migrate every hand-rolled `<button className="...">` in practice/mock/exam/results onto `<Button>` — this alone kills the height/radius/weight drift.
- **Inputs/selects**: `AuthField`'s chrome (label above, 44–48px, `rounded-xl`, brand-500/10 focus ring) becomes the one input primitive; wrap native `<select>` in a matching `Select` with a chevron (currently bare, and styled slightly differently between Practice Setup and Mistakes filters).
- **Badges/status chips**: one `Badge` (tones: neutral/brand/success/warning/danger, optional `dot`) replacing the one-off pills for "Not available yet," flagged, saved/syncing, days-to-JAMB, mistake streak.
- **Bottom navigation**: no changes — already solid (safe-area padding, 68px height, active bar, good contrast). Document as final spec.
- **Desktop sidebar**: keep the 246px dark grouped-sidebar pattern. Fix: remove/rewire the 4 dead query-param links (§4) and stop hardcoding "JAMB 2027" — read `preference.exam_year`.
- **Modal/bottom-sheet**: formalize the exam runner's existing pattern (bottom sheet on mobile with `rounded-t-3xl`, centered dialog ≥640px, full-screen reader for the passage case) as the one `Sheet` primitive; reuse it everywhere an overlay is needed, including replacing the two native `window.confirm()` calls (sign-out, clear-device) with an in-app `Sheet` confirmation.
- **Sticky mobile actions**: one shared constant for tab-bar clearance (`68px`/`4.25rem` + safe-area) so the 4.25rem/4.5rem mismatch can't recur.
- **Loading/skeleton**: add `loading.tsx` (shared pulsing `Skeleton` blocks matching each screen's card geometry) to every async route currently missing one. Keep the existing inline spinner+label pattern for in-page actions — don't skeleton those.
- **Empty/error states**: one `EmptyState` (icon+heading+body+optional CTA) and one `ErrorState` (already exists ad hoc on `/progress`) reused everywhere a list/view can be empty or throw.
- **Focus/hover/pressed/disabled**: focus-visible = 2px brand-500 ring, offset 2 (already on `Button`, extend everywhere). Hover = two allowed treatments only (bg-shift for buttons, lift+shadow for clickable cards). Pressed = add `active:scale-[0.98]` globally — currently no tap feedback anywhere. Disabled = standardize on `opacity-50` (currently 40/50/60 all appear).

## 5. Resolving the duplicate Home dashboard & duplicate quick-practice logic

One implementation, not a third:

- **Home** keeps its current server-side data computation (`activeExam`, `recent`, `weak`, `latest`, mistake count) — that's the real, correct source of truth. Its *presentation* is replaced: swap the hand-rolled header/CTA/mock/subject-performance markup for the already-built `HomeHeader` / `RecommendedPracticeCard` / `LatestMockCard` / `WeakAreasCard` (or `SubjectPerformance`), passed the exact data the page already computes. `ActiveExamCard`, `MistakesCard`, `QuickActions` are already correctly wired — untouched.
- `HomeHeader`'s "JAMB Readiness %" and "days to JAMB" need a real formula before shipping (accuracy-weighted average across recent attempts is the likely candidate) — until that's defined, ship `HomeHeader` with that chip hidden rather than inventing a number.
- **Practice Setup**'s "Quick practice" button stops computing its own hardcoded physics/waves recommendation. It becomes a plain link to `/practice?quick=1`, and the *server* resolves the actual weak-topic recommendation the same way Home does — one recommendation engine, two entry points.

## 6. Phased implementation order (lowest regression risk first)

1. **Tokens & primitives only** — `tailwind.config.ts` additions (success/danger/warning scales), extend `Button` (`dark` variant, `xl` size), new `Select`, `Badge`, `Sheet`, `Skeleton`, `EmptyState`/`ErrorState` components. Purely additive, nothing wired in yet — zero screen risk.
2. **Auth, Profile/Me, Onboarding** — apply tokens/primitives, fix minor gaps (password toggle, exam-year no longer hardcoded). No data/logic changes, isolated screens.
3. **Home consolidation** (§5) — swap in real components, delete duplicate quick-practice default, fix the sidebar's dead `mistakes`/`performance`/`bookmarks` links. Single highest-value change; touches real data wiring but confined to one route.
4. **Practice Setup** — add Past-Questions tab, timed-mode duration copy, migrate to primitives.
5. **Progress / Results / Mistakes** — apply primitives, add `loading.tsx`/`error.tsx` to every route still missing them, embed the `SubjectPerformance` section into `/progress`.
6. **Mock Setup, Exam Runner, Practice Runner, Navigator, Submission Review** — the highest-sensitivity surfaces (offline/timer state machine underneath must not change). UI-only pass: primitives, Submit-button weight, icon `aria-label`s, sticky-offset fix, exit-confirmation sheet, conflict-resolution sheet, `window.confirm()` replacement.
7. **PWA polish** — retime the install/update banner to appear after a first completed session rather than immediately on Home; add a settings row in Profile to resurface it.
8. **Cross-cutting accessibility sweep** — contrast fixes on `white/35–45` labels, focus-visible everywhere, live regions for timer/offline changes, heading structure in the exam runner. Done last since it touches every screen but changes no layout/logic.
